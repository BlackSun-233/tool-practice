## 练习1：`venv`环境变量对比
问题：将环境保存到文件中，创建一个`venv`，激活它，将其保存到另一个文件并`diff before.txt after.txt`。环境发生了什么变化？为什么`shell`更喜欢`venv`？查看激活前后的`$PATH`。运行`which deactivate`并解释`deactivate bash`函数的作用。


回答：激活虚拟环境后`PATH`将`venv`的`bin`目录放在最前面，新增`VIRTUAL_ENV`变量，实现依赖隔离。`deactivate`不是磁盘程序，是`shell`函数，用于恢复环境、退出虚拟环境。


代码：
```bash
printenv > before.txt
python3 -m venv venv_demo
source venv_demo/bin/activate
printenv > after.txt
diff before.txt after.txt
which deactivate
type deactivate
deactivate
```

输出结果：
`diff`：`PATH` 头部插入 `venv_demo/bin`，新增 `VIRTUAL_ENV` 变量
```bash

> VIRTUAL_ENV=/home/yczhang/tool-practice/exercises3/venv_demo
41a43
> VIRTUAL_ENV_PROMPT=venv_demo
44c46
< PS1=\[\e]0;\u@\h: \w\a\]${debian_chroot:+($debian_chroot)}\[\033[01;32m\]\u@\h\[\033[00m\]:\[\033[01;34m\]\w\[\033[00m\]\$ 
---
> PS1=(venv_demo) \[\e]0;\u@\h: \w\a\]${debian_chroot:+($debian_chroot)}\[\033[01;32m\]\u@\h\[\033[00m\]:\[\033[01;34m\]\w\[\033[00m\]\$ 
49c51

```

`which deactivate`：无输出


`type deactivate`：显示 `deactivate` 为 `shell` 函数，来自 `activate` 脚本
```bash
deactivate is a function
deactivate () 
{ 
    if [ -n "${_OLD_VIRTUAL_PATH:-}" ]; then
        PATH="${_OLD_VIRTUAL_PATH:-}";
        export PATH;
        unset _OLD_VIRTUAL_PATH;
    fi;
    if [ -n "${_OLD_VIRTUAL_PYTHONHOME:-}" ]; then
        PYTHONHOME="${_OLD_VIRTUAL_PYTHONHOME:-}";
        export PYTHONHOME;
        unset _OLD_VIRTUAL_PYTHONHOME;
    fi;
    hash -r 2> /dev/null;
    if [ -n "${_OLD_VIRTUAL_PS1:-}" ]; then
        PS1="${_OLD_VIRTUAL_PS1:-}";
        export PS1;
        unset _OLD_VIRTUAL_PS1;
    fi;
    unset VIRTUAL_ENV;
    unset VIRTUAL_ENV_PROMPT;
    if [ ! "${1:-}" = "nondestructive" ]; then
        unset -f deactivate;
    fi
}
```
解释：
`Shell` 查找命令按照 `PATH` 从前向后匹配，虚拟环境把自身 `bin` 目录前置，优先调用项目内 Python 工具，不和系统依赖冲突；`deactivate` 函数复原 `PATH`、清除环境变量，完成退出。


## 练习2 `pyproject.toml`小包与锁文件

问题：创建一个Python包并安装到虚拟环境中。创建一个锁文件并检查它。


回答：使用`pyproject.toml`定义Python项目，在虚拟环境安装本地包，通过`pip‑tools`生成锁文件，用来固定依赖版本。


代码：
```bash
mkdir demo_pkg
cd demo_pkg
mkdir demo_pkg
cat > pyproject.toml <<'EOF'
[build-system]
requires = ["setuptools>=61.0"]
build-backend = "setuptools.build_meta"

[project]
name = "demo_pkg"
version = "0.0.1"
EOF
touch demo_pkg/__init__.py
cd ..
python3 -m venv venv_demo2
source venv_demo2/bin/activate
pip3 install ./demo_pkg
pip3 install pip-tools
pip-compile demo_pkg/pyproject.toml
cat demo_pkg/requirements.txt
deactivate
```

输出结果：
`requirements.txt` 自动生成，文件内记录生成命令；本项目无外部依赖，没有软件包版本条目。
```bash
build  demo_pkg  demo_pkg.egg-info  pyproject.toml  requirements.txt

#
# This file is autogenerated by pip-compile with Python 3.14
# by the following command:
#
#    pip-compile --no-index demo_pkg/pyproject.toml
#

```

解释：`pyproject.toml` 是现代 Python 项目配置文件；锁文件可以锁定全部依赖的确切版本，保证多环境安装依赖完全一致。


## 练习3 手动编码与AI自动补全体验对比

问题：把同一编程任务分别用手动编码、AI自动补全各做一次，比较体验差异。

回答：两份代码运行结果一致，都可以正确统计偶数。手写更熟悉底层逻辑；AI生成代码速度快，但需要人工检查逻辑细节。

代码：
```python
#count_even_manual.py

def count_even(num_list):
    cnt = 0
    for i in num_list:
        if i % 2 == 0:
            cnt += 1
    return cnt

test = [1,2,3,4,5,6,7,8]
print(count_even(test))

#count_even_ai.py
def count_even(num_list):
    """统计列表中偶数的个数"""
    count = 0
    for num in num_list:
        if num % 2 == 0:
            count += 1
    return count


if __name__ == "__main__":
    test_data = [1, 2, 3, 4, 5, 6, 7, 8]
    print(count_even(test_data))


```
输出结果：两份程序输出均为 4


解释:手写版本变量名简单，省略文档字符串与主程序入口；AI 生成代码附带注释、文档字符串，结构更规范。AI 可以快速产出可用代码，但仍需要人工验证结果正确性。

## 练习9 `git log` 查看提交历史，`git show` 查看提交改动
问题：使用 `git log` 查看项目提交历史，查看某次提交的具体改动。


回答：初始化 Git 仓库，对 `test.txt` 执行三次修改与提交。使用`git log`查看完整提交链，每条记录包含 `commit` 哈希、作者、时间、提交说明。使用`git show <commit-id>`查看指定提交的 `diff` 改动，能够看到该次提交新增 / 删除的具体文本内容。


操作命令：
```bash
mkdir exercise_git_log
cd exercise_git_log
git init

# 第1次提交
echo "version 1" > test.txt
git add test.txt
git commit -m "commit 1: write version1"

# 第2次提交
echo "version 2" >> test.txt
git add test.txt
git commit -m "commit 2: append version2"

# 第3次提交
echo "version 3" >> test.txt
git add test.txt
git commit -m "commit 3: append version3"

# 查看全部提交历史
git log

# 查看指定commit的改动
git show ca621a62450a5865414d27fa5e9afcadf1775fb8
```

运行结果：


1. `git log`输出 3 条完整提交记录，每条包含 commit 哈希、作者、日期、提交注释。
```bash
ommit dd66ea118e6242e6843cad0cbc352e3f9fcde6bc (HEAD -> master)
Author: BlackSun-233 <fake@example.com>

    commit 3: append version3

commit ca621a62450a5865414d27fa5e9afcadf1775fb8
Author: BlackSun-233 <fake@example.com>

    commit 2: append version2

commit a02fd589e99ef6826a457f78030d6003d2469ee6
Author: BlackSun-233 <fake@example.com>
Date:   Mon Sep 7 19:02:05 2026 +0800

    commit 1: write version1
```

2. `git show`输出 `diff` 差异：第二次提交在文件末尾新增一行`version 2`。
```bash
commit ca621a62450a5865414d27fa5e9afcadf1775fb8
Author: BlackSun‑233 <fake@example.com>
Date:   Mon Sep 7 19:02:14 2026 +0800

    commit 2: append version2

diff --git a/test.txt b/test.txt
index 83baae6..0c1e739 100644
--- a/test.txt
+++ b/test.txt
@@ -1 +1,2 @@
 version 1
+version 2
```


解释：


1. `git log`：按时间倒序展示仓库全部提交记录，每个提交拥有唯一 40 位哈希 ID，用于定位版本。


2. `git show <commit‑id>`：解析单次提交，展示作者信息、提交说明与 `diff` 代码差异。


3. `diff` 格式中，`+`代表本次新增行，`‑`代表删除行，可以直观看到每次提交修改了什么内容。
